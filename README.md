# ABSA-Insights — Aspect-Based Sentiment Analysis & Data Insights Tool

> **Live web tool:** https://tshepisofrominnostation.github.io/absa-insights/
> — the full dashboard as a client-side web app: load the bundled 1,200-review
> sample, paste your own reviews, or upload a CSV, and watch the (aspect,
> sentiment, evidence) triples build in real time.

> Week 3 project, CAPACITI & Clickatell AI Bootcamp — "Sentiment Analysis & Data
> Insights" sprint, by **Freddy (Tshepiso) Thosago**, Johannesburg, ZA.

`ABSA-Insights` goes beyond one sentiment label per review. It ingests
unstructured e-commerce feedback, splits reviews into aspect-bearing clauses,
and produces **(aspect, sentiment, evidence)** triples — e.g.

> *"The battery lasts all day but delivery was late and support never replied."*
> → quality: Positive · delivery: Negative · customer service: Negative

The guide's requirements (overall sentiment, word-frequency views, dashboard,
insights report) are all built **on top of** those triples.

## Quick start

```bash
pip install -r requirements.txt
streamlit run app.py            # dashboard (bundled sample data loads by default)
```

Headless equivalents:

```bash
python run_pipeline.py          # full pipeline -> reports/ (figures, triples, aggregates)
python evaluate.py               # VADER evaluation on 100 hand-labeled reviews
python evaluate.py --model llm  # comparison LLM (needs .env, see .env.example)
python -m pytest tests/ -q       # 19 unit tests
```

## Pipeline

```
CSV ingest ──> preprocessing ──> aspect extraction ──> sentiment engine ──> dashboard / report
 (ingest.py)  (preprocess.py)   (aspects.py)        (sentiment.py,        (viz.py, app.py,
              *missing values   *clause split       compare_llm.py)        run_pipeline.py)
              *lowercase (freq) *7-aspect lexicon
              *stop words       *word-boundary match
              *normalisation
```

## Method (two-stage ABSA)

**Stage A — aspect extraction.** Reviews are split into clauses on sentence
punctuation and contrast conjunctions (but/however/although/though/except/
despite/while/whereas), so each aspect is scored on its *local* clause.
Aspects are matched with word-boundary regexes against a 7-aspect lexicon
(delivery, price, quality, customer service, product accuracy, packaging,
returns & refunds) with synonyms. A lightweight bigram pass surfaces
"emerging aspects" outside the lexicon.

**Stage B — aspect polarity.** VADER compound score on the aspect's clause:
`≥ +0.05 → Positive`, `≤ −0.05 → Negative`, else Neutral. The comparison
engine sends the whole review to an LLM under a strict JSON schema (configured
entirely via environment variables, see `.env.example`) and gracefully falls
back to VADER if the API is unavailable.

**Output schema per review** (see `run_pipeline.py` / `reports/absa_triples.csv`):

```json
{"review_id": "s0001", "overall_sentiment": "Positive", "overall_score": 0.84,
 "aspects": [{"aspect": "delivery", "sentiment": "Negative", "score": -0.42,
              "evidence": "delivery was two weeks late"}]}
```

Reviews with no detected aspect are reported as an **unassigned coverage
metric** (sample data: 68/1,200 = 5.7%).

## Data note (read this)

`data/sample_reviews.csv` is **synthetic but realistic** SA e-commerce
feedback, generated by the seeded, fully documented script
`data/generate_sample_dataset.py` (seed 42 → reproducible, 1,200 rows). It
exists so the pipeline is runnable end-to-end without scraping a live
platform. **Swap in your own CSV** (`review_id,text` columns) — nothing in the
code depends on this generator. `data/labeled_eval.csv` is 100 reviews labeled
by hand (including sarcasm, ALL CAPS, emoji, mixed sentiment and no-aspect
edge cases) for evaluation.

## Headline results (sample data, VADER baseline)

- Overall: **618 Positive (51.5%) · 346 Neutral (28.8%) · 236 Negative (19.7%)**
- Aspect coverage: **94.3%** of reviews matched at least one aspect
- Most-mentioned aspect: **delivery (451 mentions)** — mostly neutral/positive
- Biggest complaint drivers: **product accuracy** (54.1% of decided mentions
  negative) and **quality** (49.8%)
- VADER on the 100-review labeled set: overall accuracy **0.50**, macro-F1
  **0.476**; aspect-level pooled accuracy **0.383**. Lexicon gaps ("late",
  "two weeks late", "still waiting" score ~0.0) motivate the LLM comparison
  engine — see `reports/evaluation_vader.md` and run
  `python evaluate.py --model llm` to fill the comparison table.
